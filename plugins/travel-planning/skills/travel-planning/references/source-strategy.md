# 信息获取与核验策略

## 获取顺序

1. 先通过公共搜索定位官方页面、平台详情页和近期社区内容。
2. 优先读取无需登录的公开页面。成功搜索仍缺少必要字段，或必须通过日期选择器、城市选择器等交互才能得到结果时，才使用浏览器。
3. 需要登录时，只能通过环境允许的登录流程由用户完成认证。不得绕过验证码、风控、访问频率限制或付费墙。
4. 已配置的官方 API 或 MCP 优先于网页解析。使用社区工具前必须完成下文的 GitHub 工具评估。
5. 每次查询记录 `source_id`、来源类型、标题、网址、查询条件、查询时间、适用日期和查询或核验得到的关键字段，并按[行程研究工作区](research-workspace.md)即时归档。不要依赖聊天上下文保存来源。
6. 自动查询失败时立即降级为手动查询入口，不反复触发风控，不用旧缓存或第三方摘录冒充实时结果。

开始新行程时可先检索历史 workspace。历史记录只用于发现候选入口、季节经验和曾经验证过的风险点；票价、余票、天气、开放时间、签证、临时公告及交通时刻必须按本次日期重新查询。

## GitHub 工具评估与候选

发现 GitHub 项目时只先做只读评估，不自动安装或执行。至少检查：上游数据接口是否有授权、仓库归属与许可证、最近维护状态、所需凭证、外发数据、限额与费用、失败行为及是否包含反爬规避。已在本 Skill 中配置并列明边界的只读数据源可直接查询；需要新安装、新凭证、新的付费供应商或写操作时，先告知用户并获得明确同意。

| 场景 | 可评估的工具 | 使用结论 |
| --- | --- | --- |
| 中国境内地图 | [高德官方 MCP Server](https://lbs.amap.com/api/mcp-server/summary)、[百度地图官方 MCP](https://github.com/baidu-maps/mcp) | 当前通过 `$amap-maps` 引导高德 MCP；需要官方 Key，并遵守配额和展示/归因要求。 |
| 境外地点候选 | [Nominatim / OpenStreetMap](https://nominatim.org/release-docs/latest/api/Search/) | 可低频、只读检索地点与坐标候选；遵守公开服务使用政策，不并发批量抓取，入口仍需景区官网与地图平台交叉确认。 |
| 天气预报 | [weather-mcp](https://github.com/weather-mcp/weather-mcp) | 可作无 Key 预报备选；中国预警覆盖不完整，预警仍回到中央气象台或其他有中国官方预警数据的服务。 |
| 航班、火车、酒店与旅行产品 | [飞猪 FlyAI](https://github.com/alibaba-flyai/flyai-skill) | 已将上游通用 Skill 作为单一 `$flyai` 能力内置，并以官方 CLI 固定版本接入供应商 MCP API。通用发现走 Skill；航班、火车和酒店进入规划时转换为统一快照。开放式交通发现必须执行多排序覆盖；正式研究直接写入任务 `snapshots/`，候选绑定具体 offer。 |
| 航班运行与价格 | [飞常准 Aviation MCP](https://github.com/variflight/variflight-mcp) | 已通过 `$variflight` 引导固定版本官方 MCP；需要 `VARIFLIGHT_API_KEY`，适合班次、舱位价格、指定航班状态和舒适度。结果以标准快照和 `inventory_refs[]` 消费。 |
| 火车与空铁联运 | [飞常准 Tripmatch MCP](https://github.com/variflight/tripmatch-mcp) | 已通过 `$variflight` 引导固定版本官方 MCP；需要 `VARIFLIGHT_API_KEY`，结果作为平台候选；中国铁路最终回到 12306 复核。 |
| 中国景点基础资料 | [china-travel-kit](https://github.com/tczyliu/china-travel-kit) | 只作带来源和 `last_verified` 的候选数据；不代替官网的当日开放、票价、预约和临时公告。 |
| 小红书通用能力 | [autoclaw-cc/xiaohongshu-skills](https://github.com/autoclaw-cc/xiaohongshu-skills) | 已固定 commit 并作为插件 Skill/CLI 依赖接入；旅行研究默认只读，用户需加载 Chrome 扩展并自行登录，遇风控停止。具体见[小红书通用能力集成](xiaohongshu-integration.md)。 |
| 通用 Agent 搜索 | [SciPhi-AI/agent-search](https://github.com/SciPhi-AI/agent-search) | 不采用为小红书方案。它只接 Bing/AgentSearch，不提供小红书专用覆盖，且依赖较旧 Python/OpenAI SDK。 |
| 全流程规划 | [trip-planner-skill](https://github.com/skywain/trip-planner-skill) | 可借鉴分阶段研究、自检、行李/时区/复核阶梯；其航班抓取与第三方深链不能直接视为授权实时来源。 |
| 其他航班与酒店接口 | [travel-agent-skills](https://github.com/mtnrabi/travel-agent-skills) | 暂不接入；现有飞猪/飞常准覆盖不足时，才在用户明确同意凭证、外发数据和调用费用后继续评估。 |
| 铁路余票 | `Joooook/12306-mcp`、`drfccv/mcp-server-12306` 等社区项目 | 不默认启用。这类项目通常直接调用或逆向 12306 非公开网页接口，与 [12306 服务条款](https://kyfw.12306.cn/otn/regist/rule)禁止未认可爬虫访问的要求存在冲突风险。 |
| 携程酒店/航班/大巴/门票 | 非官方携程爬虫或 MCP | 不默认启用。没有可验证的授权时，只读取公开页或使用用户正常会话，失败则转手动查询。 |

## 手动查询降级

当必要字段无法自动获取时，在相应景点、交通、住宿、餐饮或天气记录中：

1. 将动态声明标记为 `to_recheck`，说明未取得的字段和失败原因。
2. 在 `action_links[]` 中加入真实的官方页、平台搜索页或地图查询页，不猜测详情深链。
3. 链接标签直接写明查询条件，例如“在 12306 查询：北京南 → 上海虹桥·10 月 3 日”，不只写“查看详情”。
4. 写明用户需输入的日期、城市/站点、人数、席别或房间等条件，以及建议复查时间。
5. 手动查询后未由用户回传结果的字段仍保持“待复核”，不根据过期页面推断。

常用固定入口：

- 景区：使用本次已定位的景区官网、官方公告页或当地文旅部门页面；没有统一入口。
- 12306：<https://www.12306.cn/index/>
- 携程：<https://www.ctrip.com/>
- 高德地图：<https://ditu.amap.com/>
- 百度地图：<https://map.baidu.com/>
- 中国天气网：<https://www.weather.com.cn/>
- 中央气象台预警：<https://www.nmc.cn/publish/alarm.html>

## 小红书调研

- 组合检索“景点 + 月份/季节 + 白天/夜景/日落 + 入口/路线/避坑”。
- 偏远景点和跨城接驳另外检索“目的地 + 月份 + 包车/司导 + 换乘/路况/行李/避坑”，重点提取实际耗时、上下车位置、道路条件、临时加价和沟通问题。
- 每个关键判断尽量参考 3 条近期内容，记录发布时间和一致/冲突结论，不复制长段原文。
- 商业推广、明显搬运或无时间信息的内容降低权重。
- 用社区信息形成“体验判断”，再用官方信息确认开放、价格、预约和安全规则。
- 包车笔记只用于发现候选、实际体验和隐性成本；司机/车辆资质、保险、最终报价和退改必须回到平台、承运公司或书面合同核验。
- 餐厅查询组合“餐厅/菜品 + 城市/商圈 + 月份/近期 + 排队/避雷/份量”。正常正餐主选交叉至少 3 篇近 12 个月独立笔记，备选至少 2 篇；逐条保留原帖链接，并记录样本数、发布时间、互动数、共同优缺点和疑似推广。来源不可用时明确记录查询词、失败原因和手动入口，不以平台首页或虚构链接补数。互动数不能换算成餐厅评分，社区内容不能证明当日营业或菜单价。
- 高德、其他点评平台和社区评分/互动必须分平台保存并显示查询时间；不得平均成一个来源不明的“综合用户评分”。

## 携程与 12306

- 查询必须绑定具体出行日期、出发站/城市和到达站/城市。
- 记录查询时间；时刻、价格和余票均标记为动态信息。
- 12306 无法访问时，先给出待复核字段和用户可执行的查询步骤，不使用第三方旧数据冒充实时数据。
- 携程上的长途大巴或包车/接驳进一步核对客运站、承运方、上车点、行李规则、报价包含项和退改；能找到官方客运或承运来源时补充官方来源。

## 置信度与冲突

- `high`：官方来源直接支持，且适用日期明确。
- `medium`：多个近期平台/社区来源一致，但缺少官方直接确认。
- `low`：来源较旧、单一或互相冲突，只能作为候选信息。
- 冲突时不静默选择；记录冲突、选择依据和需要用户出发前复核的字段。
